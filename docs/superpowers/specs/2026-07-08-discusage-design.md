# DiscUsage — дизайн приложения

**Дата:** 2026-07-08
**Статус:** утверждён

## Что это

Бесплатный личный аналог CleanDiskGo для macOS: анализ занятого места на всём диске
с treemap-визуализацией и безопасная очистка мусора. Приложение собирается из Xcode
для собственного использования — без песочницы, без App Store, полный доступ к диску
через Full Disk Access.

## Скоуп v1

Входит:

1. **Анализ диска** — сканирование всего диска (`/`), treemap-визуализация, drill-down.
2. **Большие файлы** — топ-100 самых тяжёлых файлов из результатов скана.
3. **Очистка мусора** — четыре категории: системный мусор, мусор разработчика,
   браузерные данные, локализации и прочее.

Не входит (осознанно): деинсталлятор приложений, поиск дубликатов, менеджер
автозапуска, мониторинг в фоне, поддержка внешних дисков.

## Технологии

- Swift 6 (strict concurrency), SwiftUI, macOS 15+.
- SPM-пакет `DiscUsage` (открывается в Xcode как проект) с таргетами ScanKit,
  CleanupKit, DiscUsageUI и исполняемым таргетом; `.app`-бандл собирается скриптом
  `Scripts/build-app.sh` (Info.plist + ad-hoc подпись).
- Без внешних зависимостей.

## Архитектура

```
DiscUsage.xcodeproj
├── ScanKit/        # движок сканирования, дерево размеров — без UI
├── CleanupKit/     # правила поиска мусора + исполнитель удаления — без UI
└── App/            # SwiftUI: treemap, списки, онбординг FDA
```

### ScanKit

- Параллельный обход диска через `TaskGroup`; каждая директория читается одним
  `contentsOfDirectory(at:includingPropertiesForKeys:)` с префетчем
  `totalFileAllocatedSize`, `isDirectory`, `isSymbolicLink`.
- Результат — иммутабельное дерево `FileNode` (имя, аллоцированный размер, дети).
  3–4 млн узлов целого диска умещаются в несколько сотен МБ памяти.
- Прогресс — троттлируемый `@Sendable`-колбэк (число файлов, найденные байты,
  текущий путь); отмена — штатная task cancellation.
- Размер — **аллоцированный** (реально занятый на диске), не логический.
- Точечный рескан поддерева после очистки, без полного пересканирования.

Правила обхода всего диска:

| Случай | Поведение |
|---|---|
| Firmlinks APFS | Сканируем `/`, пропускаем `/System/Volumes/{Data,Preboot,VM,Update}` — иначе двойной счёт |
| Симлинки | Не разыменовываем |
| Жёсткие ссылки (nlink > 1) | Считаем один раз, дедупликация по inode |
| `/Volumes`, `/dev` | Исключены |
| Нет доступа к папке | Узел «нет доступа», скан продолжается |
| Файл исчез во время скана | Игнорируется молча |

### CleanupKit

Декларативная таблица правил: каждое правило = категория, шаблон пути (только явный
белый список — никаких «догадок»), уровень безопасности, способ подсчёта размера.
Отдельный исполнитель удаления, за которым закреплена вся работа с файловой системой
(в тестах подменяется моком).

### App (SwiftUI)

`NavigationSplitView`, сайдбар из трёх разделов:

1. **Обзор** — treemap на `Canvas` (squarified-алгоритм). Наведение — тултип
   (путь, размер); клик — drill-down в папку; хлебные крошки для возврата;
   правый клик — контекстное меню (Показать в Finder, В Корзину, Скопировать путь).
   Цвет — по типу содержимого (медиа / код / кэши / прочее). Внизу — панель деталей
   выбранного узла.
2. **Большие файлы** — топ-100 из построенного дерева, фильтр по минимальному
   размеру, чекбоксы, массовое удаление в Корзину.
3. **Очистка** — категории с найденным объёмом, раскрытие до элементов с чекбоксами,
   бейджи безопасности (🟢/🟡), кнопка «Очистить» с подтверждением итогового объёма.

Скан запускается вручную из тулбара; результат живёт в памяти сессии.

**Онбординг Full Disk Access:** при запуске проверяем доступ пробным чтением
защищённого пути; если доступа нет — экран с кнопкой, открывающей
`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`,
и автоматическим продолжением после выдачи прав.

## Правила очистки

| Категория | Безопасность | Что ищем |
|---|---|---|
| Системный мусор | 🟢 | `~/Library/Caches/*`, `~/Library/Logs`, `/Library/Caches`, Корзина, содержимое `/private/tmp` |
| Мусор разработчика | 🟢 | Xcode DerivedData, iOS/watchOS DeviceSupport, кэши CoreSimulator, недоступные симуляторы (`simctl delete unavailable`), кэши SPM / CocoaPods / Gradle (`~/.gradle/caches`) / npm / Homebrew |
| Мусор разработчика | 🟡 | Xcode Archives (содержат релизные dSYM) |
| Браузеры | 🟡 | Кэши Safari / Chrome / Arc / Firefox — предупреждение «закройте браузер». История и cookies — отдельные тумблеры, **выключены по умолчанию**, предупреждение о разлогинах |
| Локализации и прочее | 🟡 | Старые iOS-бэкапы (`MobileSync/Backup`), вложения Mail. Неиспользуемые `.lproj` — только показ экономии; удаление только из неподписанных бандлов, т.к. **удаление `.lproj` из подписанного приложения ломает подпись** и macOS может отказаться его запускать |

## Модель безопасности удаления

- По умолчанию — **в Корзину** (`FileManager.trashItem`, откатываемо).
- «Удалить навсегда» — явная опция в диалоге подтверждения (для гигантских кэшей).
- Исключение — пункт «Корзина» в системном мусоре: её очистка по определению
  безвозвратна, что явно указывается в диалоге подтверждения.
- Только белый список путей; SIP-пути и системные корни не трогаем никогда.
- Подтверждение перед удалением: список + итоговый объём.

## Обработка ошибок

- Недоступные пути агрегируются в один баннер (не по-штучно).
- Сбой удаления одного элемента не прерывает пакет; в конце отчёт
  «удалено X, пропущено Y (причины)».
- Скан устойчив к изменению ФС во время работы.

## Тестирование

TDD, цель — 80%+ покрытие ScanKit и CleanupKit:

- **ScanKit:** фикстурные деревья во временной папке — свёртка размеров, симлинки,
  hard links, отмена, узлы «нет доступа».
- **Treemap-раскладка:** инварианты squarified — площадь пропорциональна размеру,
  прямоугольники не пересекаются, заполняют контейнер.
- **CleanupKit:** матчинг правил на фикстурах; исполнитель удаления в тестах — мок,
  реальная Корзина не затрагивается.
- UI-тесты в v1 не пишем (личный инструмент, ручная проверка).

## Решения и их причины

| Решение | Причина |
|---|---|
| Без песочницы | Личный инструмент; FDA даёт весь диск без диалогов выбора папок |
| Treemap, не sunburst | Виден весь диск сразу, проще в реализации |
| Свой движок, не `du`-обёртка | Нужны прогресс, отмена, дерево в памяти для UI |
| Корзина по умолчанию | Ошибку очистки можно откатить |
| Белый список в правилах | Эвристики в инструменте удаления недопустимы |
